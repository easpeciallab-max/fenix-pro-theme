Walk-Forward Analysis (WFA) คือกระบวนการแบ่งข้อมูลตามลำดับเวลาเป็นหลายช่วง ใช้ช่วง In-Sample พัฒนา/เลือกพารามิเตอร์ แล้วนำค่าที่เลือกไปทดสอบใน Out-of-Sample ถัดไป จากนั้นเลื่อน Window ไปข้างหน้าและทำซ้ำ วิธีนี้ช่วยตรวจทั้งตัวกลยุทธ์และกระบวนการปรับค่า ไม่ใช่ดูผลจาก Holdout เพียงช่วงเดียว

WFA ไม่ใช่ปุ่มวิเศษและไม่รับประกันว่า EA จะทำกำไร หาก Window สั้นเกินไป เกณฑ์เลือกค่าถูกเปลี่ยนภายหลัง หรือผู้ทดสอบลองรูปแบบ Window จำนวนมากแล้วรายงานเฉพาะแบบที่สวย ผล Walk-Forward ก็ Overfit ได้เช่นกัน

สารบัญ

  • WFA ทำงานอย่างไร
  • Rolling กับ Anchored Window
  • ออกแบบช่วงทดสอบ
  • เลือกพารามิเตอร์อย่างไร
  • อ่านผลรวม Walk-Forward
  • ข้อผิดพลาดที่พบบ่อย

กระบวนการ Walk-Forward แบบเห็นภาพ

  1. กำหนด In-Sample Window แรก เช่นช่วง A
  2. Optimize หรือเลือกพารามิเตอร์ด้วยกฎที่กำหนดล่วงหน้า
  3. ล็อกพารามิเตอร์และทดสอบใน Out-of-Sample ช่วง B
  4. บันทึกผล B โดยไม่แก้ค่าระหว่างช่วง
  5. เลื่อน Window: ใช้ข้อมูลช่วงถัดไปเป็น IS และทดสอบ OOS ใหม่
  6. เชื่อม OOS ทุกช่วงเป็น Walk-Forward Equity
  7. ประเมินความเสถียร ไม่เลือกดูเฉพาะ Window ที่กำไร

ข้อมูล OOS ของแต่ละรอบต้องไม่ถูกใช้เลือกรอบนั้น หากเห็นผลแล้วเปลี่ยนกฎ Selection ควรถือว่าเริ่ม Research Version ใหม่และต้องมีข้อมูลใหม่สำหรับยืนยัน

พื้นฐานเรื่องชุดข้อมูลอ่านที่ In-Sample และ Out-of-Sample ของ EA

Rolling Window กับ Anchored Window

Rolling Window

ความยาว IS คงที่และเลื่อนทั้งจุดเริ่ม/จุดจบ ข้อมูลเก่าที่สุดหลุดออกทุกครั้ง เหมาะเมื่อเชื่อว่าข้อมูลล่าสุดเกี่ยวข้องกับ Regime ปัจจุบันมากกว่า แต่ Sample อาจเล็กและ Parameter เปลี่ยนบ่อย

Anchored Window

จุดเริ่ม IS คงเดิม ส่วนปลายขยายไปข้างหน้า ใช้ข้อมูลสะสมมากขึ้นและ Parameter อาจนิ่งกว่า แต่ข้อมูลเก่าที่โครงสร้างตลาดเปลี่ยนไปยังมีน้ำหนักอยู่

ประเด็น Rolling Anchored
ข้อมูลเก่า ตัดออกตาม Window คงไว้ทั้งหมด
ตอบสนอง Regime เร็วกว่าแต่ Noise สูงขึ้นได้ ช้ากว่าแต่ Sample ใหญ่ขึ้น
ความถี่ Re-optimize มักใช้รอบคงที่ ใช้รอบคงที่ได้เช่นกัน

ไม่มีแบบที่ชนะเสมอ ต้องเลือกจากเหตุผลของกลยุทธ์และล็อกวิธีก่อนเห็นผล OOS

เลือกความยาว IS/OOS อย่างไร

อย่าเริ่มจากสัดส่วนตายตัวอย่าง 12 เดือน/3 เดือนโดยไม่ดู Trade Frequency และ Regime เกณฑ์ที่ควรพิจารณา:

  • IS มี Trade พอให้ Optimization แยก Signal จาก Noise
  • ครอบคลุม Cycle ที่กลยุทธ์อาศัย เช่น Trend/Volatility
  • OOS ยาวพอให้เกิด Trade หลายชุด แต่ไม่ยาวจน Parameter ไม่มีโอกาสปรับตามแผน
  • จำนวน Window มากพอเห็น Distribution ไม่ใช่ 2 รอบ
  • ช่วงข่าว/วิกฤตไม่ถูกตัดออกโดยไม่มีเหตุผล
  • ต้นทุนและ Symbol Specification สม่ำเสมอข้าม Window

สำหรับ EA ที่เทรดน้อย อาจต้องใช้ IS หลายปีและ OOS ยาวขึ้นเพื่อให้ Sample มีความหมาย ส่วนระบบ Intraday ที่เทรดถี่อาจใช้ Window สั้นกว่า แต่ยังต้องครอบคลุม Regime และต้นทุนที่เปลี่ยน

อย่าเลือกพารามิเตอร์จาก Net Profit สูงสุดอย่างเดียว

กฎ Selection ควรหาความเสถียร ไม่ใช่ Peak เดียว ตัวอย่างแนวทาง:

  • ตัด Pass ที่จำนวน Trade ต่ำเกินไป
  • กำหนดเพดาน Equity Drawdown
  • ดู Recovery/Profit Factor ร่วมกับ Distribution
  • เลือก Parameter Plateau ที่ค่าข้างเคียงให้ผลใกล้กัน
  • Stress Test Spread/Delay ก่อนเลือก
  • จำกัด Turnover และ Exposure ตามข้อกำหนดจริง
  • บันทึกกฎ Tie-break เมื่อหลายชุดผ่าน

การเปลี่ยนเกณฑ์ในแต่ละ Window ตามผลที่เห็นทำให้กระบวนการไม่ใช่ระบบเดียวกัน ควรเขียน Selection Algorithm หรือ Checklist ที่ผู้อื่นทำซ้ำได้

ทำ Walk-Forward ใน MT5 ได้อย่างไร

MT5 มี Forward Optimization สำหรับแบ่งส่วนท้ายของช่วงเป็น Forward และนำผลที่เลือกจาก Back Period ไปทดสอบ แต่ Walk-Forward หลาย Window ต้องรันกระบวนการซ้ำโดยเลื่อน Date หรือใช้เครื่องมือ/สคริปต์จัดชุดงานเพิ่มเติม

  1. บันทึกไฟล์ EA, SET และ Tester Settings
  2. กำหนด IS/OOS Calendar ทุก Window ล่วงหน้า
  3. Optimize IS ด้วย Range และ Criterion เดิม
  4. เลือก Pass ด้วยกฎเดิม
  5. Single Test บน OOS และ Export Report
  6. เชื่อม Deal/Equity OOS ตามเวลาโดยไม่รวม IS
  7. บันทึก Parameter ที่ถูกเลือกในแต่ละ Window

อ่านผล Walk-Forward จากอะไร

  • OOS Net/Expectancy: รวมทุก Window ไม่เลือกเฉพาะกำไร
  • Window Pass Rate: กี่รอบอยู่ในเกณฑ์ที่กำหนด
  • Worst OOS Drawdown: ความเสียหายสูงสุดและ Recovery Time
  • Parameter Stability: ค่าเปลี่ยนรุนแรงทุก Windowหรือไม่
  • IS/OOS Degradation: ผล OOS ลดลงจาก IS มากแค่ไหน
  • Cost Sensitivity: เมื่อเพิ่มต้นทุนผลยังรับได้หรือไม่
  • Regime Dependence: Window ที่พังมีลักษณะร่วมอะไร

Equity ที่เชื่อมต้องใช้เฉพาะ OOS และจัด Position ที่คาบข้ามรอยต่ออย่างสม่ำเสมอ หากทุกรอยต่อบังคับปิดออเดอร์แต่ระบบจริงไม่ทำ ต้องระบุผลกระทบดังกล่าว

ข้อผิดพลาดที่ทำให้ WFA ดูดีกว่าความจริง

  • ลอง Window Length หลายสิบแบบแล้วเลือกเส้นดีที่สุด
  • แก้ Selection Rule หลังเห็น OOS
  • ใช้ Parameter Range กว้างมากโดยไม่มีสมมติฐาน
  • ไม่รวม Commission/Slippage/Delay ในทุก Window
  • รวม IS Equity เข้า Report เพื่อให้เส้นดูสวย
  • ทิ้ง Window ที่ขาดทุนเพราะเรียกว่า Outlier ภายหลัง
  • จำนวน Trade ต่อ Window ต่ำจนค่าผันผวนสูง
  • ใช้ข้อมูลอนาคตในการจัด Regime หรือเลือก Symbol

หลังผ่าน WFA ยังควรทำ Monte Carlo และ Forward Test ที่ไม่ใช้ข้อมูลในการปรับค่า อ่านภาพรวมการทดสอบจริงที่ Forward Test EA และปัญหา Parameter Fitting ที่ Over-Optimization

คำเตือนความเสี่ยง: Walk-Forward เป็นเครื่องมือประเมินความทนทานจากอดีต ไม่ยืนยันว่า Regime หรือความสัมพันธ์เดิมจะคงอยู่ ระบบที่ผ่านยังขาดทุนและล้มเหลวได้
