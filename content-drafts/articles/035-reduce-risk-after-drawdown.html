เมื่อพอร์ต EA เข้า Drawdown สิ่งแรกไม่ใช่การเพิ่ม Lot เพื่อเอาคืนหรือเปลี่ยน Parameter จน Backtest รอบล่าสุดสวยขึ้น แต่คือหยุดความเสี่ยงที่ไม่จำเป็น เก็บหลักฐาน และจำแนกว่าความเสียหายอยู่ใน Distribution ที่เตรียมไว้หรือเป็นสัญญาณว่า Execution, Software หรือสมมติฐานของระบบเปลี่ยน

Drawdown เป็นส่วนหนึ่งของระบบที่มีความเสี่ยง แต่ไม่ได้แปลว่าทุก Drawdown ต้องทนต่อไป การตัดสินใจที่ดีต้องมีกฎก่อนเกิดเหตุ: ระดับเตือน ระดับลดความเสี่ยง ระดับหยุด และหลักฐานที่ต้องผ่านก่อนกลับมารัน

สารบัญ

  • สิ่งที่ต้องทำทันที
  • แยกสาเหตุ Drawdown
  • วิธีลด Lot โดยไม่หลอกตัวเอง
  • เกณฑ์กลับมารัน
  • สิ่งที่ไม่ควรทำ
  • ตัวอย่าง Drawdown Playbook

ขั้นแรก: ป้องกันไม่ให้ข้อมูลหายและความเสี่ยงเพิ่ม

  1. หยุดเปิด Position ใหม่: ใช้ Pause/Disable Entry ตามวิธีของ EA โดยไม่ลบข้อมูลก่อนเก็บหลักฐาน
  2. ตรวจ Open Risk: รวม Stop, Basket, Pending, Margin และ Correlated Position ทั้งบัญชี
  3. เก็บหลักฐาน: Export Statement/Report, Expert Log, Journal, Screenshot, Parameter และ Version
  4. ยืนยันการทำงาน: ตรวจ VPS, Connection, AutoTrading, Symbol Specification และ Error Code
  5. ทำตาม Exit Plan: ไม่ปิด/ถัวเฉลี่ยด้วยอารมณ์ ให้ใช้กฎที่อนุมัติไว้หรือ Escalate เมื่ออยู่นอก Scenario

หาก Drawdown ใกล้ Risk Limit การป้องกันบัญชีมี Priority สูงกว่าการรักษา Position เพื่อหวังกลับมา การเปลี่ยน Stop หรือเพิ่มทุนโดยไม่มีแผนจะทำให้วิเคราะห์ภายหลังยากขึ้นและอาจเพิ่ม Risk of Ruin

จำแนกสาเหตุออกเป็นสี่กลุ่ม

1. Statistical Drawdown

ผลอยู่ในช่วงที่ Backtest, Out-of-sample และ Stress Test เคยแสดง ทั้ง Trade Pattern, Cost และ Execution ไม่ผิดปกติ กรณีนี้อาจเป็น Variance ปกติ แต่ยังต้องตรวจว่าความเสี่ยงปัจจุบันเหมาะกับผู้ใช้หรือไม่

2. Market Regime Shift

Volatility, Trend, Correlation หรือ Liquidity ต่างจาก Sample ที่ระบบได้เปรียบ เช่น Trend Following เจอ Whipsaw ต่อเนื่อง หรือ Scalping เจอ Spread/Execution เปลี่ยน ต้องทดสอบโดยแบ่ง Regime ไม่สรุปจากกำไรขาดทุนรวมอย่างเดียว

3. Execution/Environment Problem

Spread, Commission, Slippage, Latency, VPS, Contract Specification หรือ Trading Hours เปลี่ยน ทำให้ Live Result แย่กว่าทฤษฎี ตรวจ Expert/Journal Log และเปรียบเทียบ Deal-by-deal กับ Signal/Backtest

4. Software/Configuration Error

Version ผิด, Preset ผิด, Magic Number ซ้ำ, Auto Lot คำนวณผิด, Timezone หรือ News Filter ไม่ทำงาน กลุ่มนี้ต้องหยุดจนแก้และ Retest ไม่ควรลด Lotแล้วปล่อย Bug ทำงานต่อ

ใช้คำอธิบายพื้นฐานที่ Drawdown คืออะไร และอ่าน Equity/Balance เพิ่มที่ วิธีอ่าน Equity Curve

ลด Lot อย่างไรให้มีเหตุผล

การลด Lot ลดความไวของ P/L ต่อการเคลื่อนไหวราคา แต่ไม่ได้แก้ Edge ที่เสียหรือ Bug การลดควรผูกกับ Risk Budget และ Validation State ไม่ใช่ลดแบบสุ่ม:

  1. คำนวณ Equity ปัจจุบันและ Open Risk หลังรวมทุกระบบ
  2. กำหนด Risk ต่อ Trade/Basket ใหม่จาก Equity ไม่ใช่ Initial Balance
  3. ลด Portfolio Exposure Cap และจำนวน Position พร้อมกัน
  4. ตรวจ Lot ขั้นต่ำ หากยังเสี่ยงเกินงบให้หยุดแทนการฝืนเปิด
  5. Forward Test ด้วย Lot ต่ำ/บัญชี Demo ก่อนเพิ่ม Scale
  6. เพิ่ม Lot กลับเป็นขั้นเมื่อ Metric และจำนวนตัวอย่างผ่านเกณฑ์

ห้ามใช้ “ต้องเพิ่ม Lot เพราะทุนลด” เพื่อเร่ง Recovery เพราะเป็นการเพิ่มสัดส่วนความเสี่ยงในช่วงที่ความไม่แน่นอนสูง อ่าน Fixed Lot กับ Auto Lot และ Money Management

เงื่อนไขกลับมารันควรวัดได้

ด้าน หลักฐานก่อน Resume
Software Version/Checksum/Parameter ถูกต้องและทดสอบ Regression ผ่าน
Execution Spread, Slippage, Latency และ Error อยู่ในเกณฑ์ที่กำหนด
Strategy Live Deviation มีคำอธิบายและยังอยู่ใน Distribution/Scenario ที่รับได้
Risk Lot, Exposure, Equity Stop และ Daily Limit ถูกลด/ตั้งใหม่
Operations VPS, Monitoring, Alert และผู้รับผิดชอบพร้อม

การเปิดใหม่ควรเป็น Phased Restart เช่น Demo/Observation, Small Live, Limited Symbols แล้วจึง Scale ตาม Checkpoint ไม่เปิด Full Risk ทันทีเพียงเพราะมี Trade ชนะหนึ่งครั้ง

สิ่งที่ทำให้ Drawdown แย่ลง

  • เพิ่ม Lot หรือเปิดระบบใหม่เพื่อชดเชย Loss โดยไม่รวม Exposure
  • เปลี่ยน Parameter หลายค่าพร้อมกันจนหาสาเหตุไม่ได้
  • Optimize ด้วยช่วง Drawdown ล่าสุดแล้วเรียกว่าระบบได้รับการแก้ไข
  • ลบ EA/Log หรือ Restart ก่อนเก็บหลักฐาน
  • เติมเงินเพื่อยืด Basket โดยไม่มี Stop ใหม่
  • หยุดระบบหลังแพ้และเปิดหลังชนะจากสัญญาณสั้น ๆ แบบไม่มีเกณฑ์
  • ปกปิด Drawdown ด้วยการดู Balance โดยไม่ดู Equity

Drawdown Playbook ที่ควรเขียนไว้

เอกสารหนึ่งหน้าควรมีระดับและผู้ตัดสินใจ:

  • Watch: Drawdown ถึงระดับสังเกต ตรวจข้อมูลแต่ยังทำตามแผน
  • Reduce: ลด Lot/จำนวน Position และเพิ่ม Monitoring
  • Pause: หยุด Entry เก็บหลักฐานและ Root-cause Analysis
  • Emergency: ทำตาม Account Protection Rule เมื่อเกิด Bug/Execution Failure
  • Resume: ระบุ Test, Reviewer, Lot เริ่มต้น และ Checkpoint

ระดับเหล่านี้ต้องมาจากความสามารถรับความเสี่ยงจริงและ Distribution ของระบบ ไม่คัดลอกเปอร์เซ็นต์จากผู้อื่น เชื่อมกับ Risk of Ruin, Daily Loss Limit และ Equity Stop

สรุป: แผนรับมือ Drawdown ที่ดีแยกการป้องกันบัญชี การเก็บหลักฐาน การวิเคราะห์สาเหตุ และการกลับมารันออกจากกัน การลด Lot เป็นเพียงเครื่องมือหนึ่ง ไม่ใช่คำตอบหาก Strategy หรือระบบปฏิบัติการมีปัญหา

คำเตือนความเสี่ยง: Drawdown ในอดีตไม่ใช่เพดานในอนาคต การลด Lot, Stop หรือการหยุดระบบไม่สามารถรับประกันว่าจะจำกัดผลขาดทุนได้ทุกสถานการณ์ การเทรดแบบใช้ Leverage มีความเสี่ยงสูง โปรดประเมินความเหมาะสมและใช้เงินที่พร้อมรับความเสี่ยงเท่านั้น อ่าน คำเตือนความเสี่ยงฉบับเต็ม
