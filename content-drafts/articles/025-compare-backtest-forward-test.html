การเปรียบเทียบ Backtest กับ Forward Test ไม่ใช่การเอา Net Profit สองตัวมาวางข้างกัน เพราะช่วงเวลา ความยาว Sample และสภาพ Execution ต่างกัน เป้าหมายคือดูว่า “พฤติกรรมที่คาดจากแบบจำลองยังปรากฏในข้อมูลใหม่หรือไม่” ภายใต้ EA Version, Preset และ Risk เดียวกัน

Forward Test ไม่ควรตรงกับ Backtest ทุก Trade ราคาจริงมี Spread, Slippage, Delay และข้อมูล Tick ที่ต่าง แต่ถ้าความถี่ Trade, ทิศทาง Risk หรือ Drawdown แตกต่างมาก ต้องหาสาเหตุก่อนสรุปว่าเป็นความผันผวนปกติ

สารบัญ

  • ทำสองชุดให้เทียบกันได้
  • Metric ที่ควรเปรียบเทียบ
  • ความต่างที่เกิดได้ตามปกติ
  • สัญญาณที่ต้องหยุดตรวจ
  • หลีกเลี่ยงการเลือกช่วงสวย
  • กระบวนการตัดสินใจ

ล็อกเงื่อนไขก่อนเริ่ม Forward Test

  • ไฟล์ EA และ Version เดียวกัน
  • Preset/Input เดียวกัน
  • Symbol, Suffix, Contract Specification ใกล้กัน
  • Account Type, Currency และ Leverage ที่บันทึกไว้
  • Risk/Lot Formula เดียวกัน
  • Timezone/Server Time และ Session ตรง
  • Commission/Swap และต้นทุนที่ทราบ
  • วันเริ่ม Forward ที่กำหนดก่อนเห็นผล

หากเปลี่ยน Preset ระหว่าง Forward ต้องแบ่ง Version ของการทดสอบ ไม่รวมผลก่อนและหลังแล้วเรียกว่า Track Record เดียว เพราะระบบที่ทดสอบไม่เหมือนเดิม

อ่านพื้นฐานที่ Forward Test EA คืออะไร และวิธีตั้งอดีตที่ วิธี Backtest EA บน MT5

Metric ที่ควรเทียบ

Trade Frequency

Normalize เป็น Trade ต่อเดือน/Session และแยกตาม Symbol หาก Forward ไม่มี Trade ทั้งที่ Backtest คาดว่าจะมีจำนวนมาก ตรวจ Timezone, Symbol, Filter และ Data ก่อน

Average Trade หลังต้นทุน

ดูค่าเฉลี่ยและ Median ไม่ใช้ Net Profit รวม Forward สั้นอาจมี Trade น้อยและ Winner ใหญ่ยังไม่เกิด จึงต้องดู Distribution ประกอบ

Win Rate และ Payoff Ratio

Win Rate ต่างได้จาก Sample แต่หากทิศทางผิดมากให้ตรวจ Execution และ Logic ใช้ Win Rate คู่กับ Average Win/Loss ไม่แยกดูค่าเดียว

Drawdown และ Losing Streak

เปรียบเทียบกับ Distribution จาก Backtest/Monte Carlo ไม่ใช้ Maximum Backtest เป็นเพดานแน่นอน หาก Forward แตะ Risk Budget ให้ทำตาม Kill Criteria

Exposure และ Holding Time

ดูจำนวน Position พร้อมกัน Lot รวม ระยะถือ และเวลาที่เปิด หากต่างมากอาจมาจาก Spread/News/Session หรือ Symbol Specification

ทำไมผลจึงไม่เหมือนกัน

  • Backtest ใช้ Tick History คนละ Server
  • Spread/Commission/Swap จริงต่างจากค่าจำลอง
  • Network Delay และ Slippage
  • EA/MT5 หยุดจาก VPS Restart หรือ Connection
  • ข่าว/Calendar Data เปลี่ยนหรือแก้ย้อนหลัง
  • Symbol Suffix และ Trading Session ต่าง
  • Forward Sample สั้นและอยู่คนละ Regime
  • Manual Intervention หรือการเปลี่ยน Setting

ความต่างแต่ละข้อควรมีหลักฐานจาก Experts/Journal, Deal History และ Test Setting ไม่ใช้คำว่า “ตลาดเปลี่ยน” ครอบทุกกรณีโดยไม่ตรวจระบบ

สัญญาณที่ไม่ควรปล่อยผ่าน

  • Forward เปิด Trade ที่ Backtest ไม่มีในเวลา/ข้อมูลเดียวกันจำนวนมาก
  • Lot, Stop หรือ Magic ไม่ตรง Preset
  • มี Gap จาก Terminal Offline แต่ Report ไม่ระบุ
  • Forward Drawdown เกิน Risk Limit ที่กำหนด
  • Average Trade ต่ำกว่าต้นทุนจริงอย่างต่อเนื่อง
  • ระบบต้องเปลี่ยนค่าบ่อยเพื่อให้กลับมากำไร
  • ผู้รายงานเปลี่ยน Account/EA Version โดยไม่เปิดเผย
  • แสดงเฉพาะ Balance ไม่แสดง Equity/Open Positions

กรณีเหล่านี้ไม่พิสูจน์ว่า EA “ไม่ดี” แต่ทำให้หลักฐานเดิมไม่พอ ต้องหยุดเพิ่มความเสี่ยงและตรวจ Root Cause

อย่าเลือกเฉพาะช่วงสวย

ข้อผิดพลาดทั่วไปคือเริ่มนับ Forward หลัง Drawdown จบ หยุด Report ก่อนขาดทุน หรือสร้างบัญชีใหม่เมื่อผลไม่ดี วิธีลด Bias:

  • ประกาศ Start Date และ Account ก่อนเริ่ม
  • เก็บผลต่อเนื่องรวม Deposit/Withdrawal
  • รายงาน Version/Preset Change
  • แสดง Equity, Open Trades และ History
  • ไม่ลบเดือนขาดทุนจากค่าเฉลี่ย
  • ใช้ช่วงเวลาเดียวกันเมื่อเทียบ Preset
  • เก็บ Screenshot/Report พร้อม Timestamp

หากใช้บัญชีสาธารณะจากบริการ Track Record ให้ตรวจว่า Verified Track Record, Trading Privileges, Broker/Server และ History เริ่มเมื่อใดตามความสามารถของแพลตฟอร์มนั้น ไม่ใช้ Badge เดียวแทนการอ่านรายละเอียด

ทำ Trade Reconciliation เพื่อหาความต่าง

เมื่อมีข้อมูล Forward มากพอ ให้จับคู่ Trade กับ Backtest ในช่วงเวลาเดียวกันโดยใช้ Signal Time, Symbol, Direction และ Magic/Comment ไม่ควรจับคู่จากราคาอย่างเดียวเพราะ Slippage ทำให้ราคาต่างได้ จากนั้นแบ่งผลเป็นสี่กลุ่ม: พบทั้งสองชุด, มีเฉพาะ Backtest, มีเฉพาะ Forward และพบทั้งคู่แต่ Exit ต่างกัน

กลุ่มที่หายไปช่วยชี้สาเหตุ เช่น Spread Filter ปิด Entry, Terminal Offline, News Data ต่าง หรือ Session Offset ผิด ส่วน Exit ต่างอาจมาจาก Tick Sequence, Delay, Trailing หรือ Manual Action การทำตารางนี้มีประโยชน์กว่าการบอกว่า Net Profit “ใกล้กัน” เพราะทำให้ตรวจพฤติกรรมระดับกฎได้

  • บันทึก Timestamp ทั้ง Server Time และ UTC
  • เก็บ Order/Deal Ticket โดยปิดข้อมูลส่วนตัวเมื่อเผยแพร่
  • ระบุเหตุผลของรายการที่จับคู่ไม่ได้
  • สรุปอัตราความสอดคล้องแยก Entry และ Exit
  • เก็บ Log รอบรายการที่ผิดปกติเพื่อยืนยัน Root Cause

Framework ตัดสินใจหลังมี Forward Data

  1. ตรวจ Integrity: Uptime, Version, Preset, Deposit/Withdrawal
  2. Normalize Metric ตามเวลาและจำนวน Trade
  3. เทียบกับ Backtest Range/Monte Carlo ไม่เทียบจุดเดียว
  4. อธิบายความต่างด้วย Log และต้นทุน
  5. ตรวจว่าผ่านเกณฑ์ที่กำหนดก่อนเริ่มหรือไม่
  6. หากแก้ระบบ ให้เริ่ม Validation Version ใหม่
  7. ตัดสินใจ Continue, Reduce Risk, Pause หรือ Retire ตามกฎ

ใช้ Checklist ประเมิน EA เพื่อไม่ลืมด้าน License/Support และดูข้อมูล FENIX PRO ที่ หน้า Forward Test โดยอ่านเงื่อนไขร่วมกับ หน้า Backtest

ระยะ Forward ที่เหมาะสมขึ้นกับความถี่ Trade และ Regime ไม่ใช่จำนวนวันอย่างเดียว หากระบบเทรดน้อย การเห็นกำไรหนึ่งเดือนอาจเกิดจาก Trade ไม่กี่รายการ ควรรอให้ Sample ถึงเกณฑ์ที่กำหนดล่วงหน้าและครอบคลุมทั้งช่วงที่ระบบได้เปรียบและเสียเปรียบก่อนเพิ่มความเสี่ยง

คำเตือนความเสี่ยง: Forward Test ใกล้สภาพจริงกว่า Backtest บางด้าน แต่ยังอาจเป็น Demo, Sample สั้น หรือไม่สะท้อนเงินทุนของผู้ใช้ ผลทั้งสองแบบไม่รับประกันผลในอนาคต
