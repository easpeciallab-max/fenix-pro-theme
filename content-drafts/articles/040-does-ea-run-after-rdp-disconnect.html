คำตอบสั้นคือ เมื่อปิด Remote Desktop แบบ Disconnect แอปใน Session มักยังทำงานต่อ ตราบใดที่ VPS ยังเปิดและ Session ยังไม่ถูก Log off แต่ถ้ากด Sign out, Restart/Shut down, ผู้ให้บริการยุติ Session หรือมี Group Policy ตั้งเวลาปิด Disconnected Session โปรแกรม MT5 และ EA อาจหยุด

ความสับสนเกิดจากคำว่า “ปิด RDP” ครอบคลุมหลายการกระทำที่ผลต่างกัน ผู้ใช้ต้องรู้ว่าตน Disconnect หรือ Log off และต้องตรวจ Process/Heartbeat จากหลักฐาน ไม่อาศัยเพียงสมมติฐานว่าหน้าต่างหายแล้วระบบยังทำงาน

สารบัญ

  • สถานะ RDP ที่ต่างกัน
  • อะไรทำให้ EA ทำงานต่อ
  • กรณีที่ EA หยุด
  • วิธีออกจาก RDP อย่างถูกต้อง
  • วิธียืนยันว่า EA ยังทำงาน
  • ตรวจ Session Policy

Disconnect, Lock, Sign out และ Restart

การกระทำ ผลโดยทั่วไป
Disconnect/ปิดหน้าต่าง RDP Session ยังอยู่บน VPS และแอปทำงานต่อ หาก Policy ไม่ Log off
Lock Session ยัง Active/Locked แอปมักทำงานต่อ
Sign out/Log off จบ User Session และปิดโปรแกรมใน Session
Restart/Shut down หยุดระบบ/Process และต้อง Auto-start หลัง Boot
Provider Rebuild/Terminate เครื่องหรือ Disk อาจถูกลบตามคำสั่ง ต้องมี Backup/Recovery

Microsoft ระบุว่าเมื่อใช้ Disconnect แอปจะยัง Active ตราบใดที่ Session บน Remote PC ยังคง Active และคำสั่ง tsdiscon จะตัดการเชื่อมต่อโดยแอปที่กำลังรันยังอยู่เมื่อกลับมาเชื่อมใหม่ อย่างไรก็ตาม Group Policy สามารถกำหนด Time Limit ให้ Disconnected Session ถูก Log off ภายหลังได้

เงื่อนไขที่ EA ต้องมีเพื่อทำงานต่อ

  • VPS Powered on และ Windows ไม่ Restart
  • User Session ยังไม่ถูก Log off
  • Process terminal64.exe ยังทำงาน
  • MT5 เชื่อม Trading Server และรับ Tick
  • AutoTrading/Allow Algo Trading เปิดตามนโยบาย
  • EA ติดอยู่บน Chart และไม่มี Critical Error
  • ระบบไม่ Sleep/Hibernate หรือถูก Provider Suspend

RDP เป็นช่องทางแสดงผลและควบคุม Desktop ไม่ใช่สิ่งที่ EA ใช้ติดต่อ Broker โดยตรง เมื่อ Disconnect Client ที่บ้าน การประมวลผลยังอยู่บน VPS แต่หากผู้ใช้กด Sign out Windows จะปิด Process ที่ผูกกับ User Session

เหตุการณ์ที่ดูเหมือน “ปิด RDP แล้ว EA หยุด”

Session Timeout ถูกตั้งเป็น Log off

ผู้ให้บริการหรือ Group Policy อาจกำหนดให้ Disconnected Session ถูกจบหลังเวลาหนึ่ง ต้องตรวจ Remote Desktop Session Host > Session Time Limits และข้อกำหนด Provider

ปิด MT5 ก่อนปิดหน้าต่าง

การกด X ที่หน้าต่าง MT5 หรือ Exit Platform ปิด EA จริง ต่างจากกด X ที่หน้าต่าง Remote Desktop Client ต้องอ่านชื่อหน้าต่างก่อนยืนยัน

VPS Restart ภายหลัง

Windows Update หรือ Maintenance อาจ Restart หลัง Disconnect หากไม่มี Auto-start ระบบจะหยุดจนผู้ใช้กลับมาเปิด อ่าน วิธีตั้ง MT5 เปิดอัตโนมัติหลัง VPS Restart

Process ค้างแต่หน้าต่างยังอยู่

เมื่อกลับเข้า VPS เห็น MT5 ไม่ได้แปลว่ากำลังรับ Tick ตรวจ Connection, เวลา Market Watch และ Log หาก UI ค้างอาจต้องใช้ Monitoring ภายนอกแทนการดูภาพหน้าจอ

วิธีออกจาก RDP โดยไม่ Log off

  1. บันทึก/ตรวจ Setting ที่จำเป็น แต่ไม่กด Exit MT5
  2. ตรวจ Connection, AutoTrading และสถานะ EA
  3. ปิดหน้าต่าง Remote Desktop Client แล้วเลือก Disconnect หากมีคำถามยืนยัน
  4. หลีกเลี่ยงเมนู Start > Sign out
  5. รอช่วงหนึ่งแล้วเชื่อมกลับ ตรวจว่า Uptime/Log เดินต่อเนื่อง

ทีมที่ดูแลหลายเครื่องควรใช้คำว่า Disconnect และ Sign out ให้ตรงกันใน Runbook พร้อม Screenshot เมนูจริงของ Client ที่ใช้ เพราะ Windows App, Remote Desktop Connection และ Mobile Client อาจจัดวางปุ่มต่างกัน

พิสูจน์จาก Heartbeat ไม่ใช่ความเชื่อ

วิธีตรวจที่ดีกว่าการกลับเข้า RDP ทุกชั่วโมง:

  • EA เขียน Heartbeat พร้อม Server Time ลง Log/File ตามรอบ
  • Monitoring ตรวจ Process, CPU และเวลาแก้ไข Log ล่าสุด
  • Alert เมื่อไม่มี Tick/Heartbeat เกิน Threshold
  • ตรวจ Expert/Journal ว่าไม่มี No Connection/Error
  • ส่งสถานะไปช่องทางภายนอก VPS โดยไม่เผยข้อมูลบัญชีลับ

แยก Heartbeat ของ “Process อยู่” จาก “Strategy Ready” Process อาจอยู่แต่ Account Logout หรือ Algo Trading ปิด สถานะพร้อมควรรวม Connection, Account, Symbol Sync, EA State และ Risk Lock

ตรวจ Policy และทดสอบกับ Provider

บน Windows Server ให้ตรวจ Group Policy/Local Policy เรื่อง:

  • Set time limit for disconnected sessions
  • End session when time limits are reached
  • Idle session limit
  • Active session limit
  • ผู้ให้บริการมี Automation ปิดเครื่องเมื่อ Idle หรือไม่

อย่าแก้ Policy ที่ไม่เข้าใจบน Managed VPS ให้ถามผู้ให้บริการก่อน และทดสอบในช่วงที่ไม่มี Open Risk หาก Policy องค์กรบังคับ Log off อาจต้องเปลี่ยน Architecture/Service Hosting แทนการหลีกเลี่ยง Security Control

กรณีใช้หลาย User หรือเปิด Session ใหม่

หากกลับเข้า VPS แล้ว Windows สร้าง User Session ใหม่ Terminal ใน Session เก่าอาจยังทำงาน ทำให้ผู้ใช้เปิด MT5 ซ้ำใน Session ใหม่และส่งคำสั่งซ้ำได้ ตรวจ Task Manager แบบ All users, ใช้บัญชีเดียวตาม Runbook และกำหนด Process/Instance Guard

อ่านพื้นฐาน VPS เพิ่มที่ VPS สำหรับ EA และขั้นตอนเชื่อมต่อที่ คู่มือใช้งาน VPS บน Windows

สรุป: Disconnect โดยทั่วไปปล่อย Session และ EA ทำงานต่อ ส่วน Sign out และ Restart หยุด Process แต่ผลจริงขึ้นกับ Session Policy และ Provider ต้องยืนยันด้วย Heartbeat/Log และมี Auto-start/Alert รองรับเหตุ Restart

คำเตือนความเสี่ยง: VPS และ RDP อาจขัดข้องหรือถูกยุติ Session ได้ การปล่อย EA ทำงานโดยไม่ Monitoring เพิ่มความเสี่ยง ผู้ใช้ต้องติดตาม Position และมีแผนฉุกเฉิน การเทรดมีความเสี่ยงสูง อ่าน คำเตือนความเสี่ยงฉบับเต็ม
