Daily Loss Limit คือกฎหยุดความเสี่ยงเมื่อผลขาดทุนภายในวันถึงเกณฑ์ที่กำหนด จุดประสงค์ไม่ใช่ทำนายว่าหลังจากหยุดแล้วตลาดจะกลับตัวหรือไม่ แต่เพื่อจำกัดวันที่ผิดปกติ ป้องกันการเปิดซ้ำต่อเนื่อง และสร้างเวลาสำหรับตรวจระบบก่อนความเสียหายขยาย

กฎที่เขียนเพียง “ขาดทุนรายวันถึง X แล้วหยุด” ยังใช้จริงไม่ได้ ต้องระบุว่าเริ่มนับวันเมื่อใด ใช้ Balance หรือ Equity รวม Floating Loss หรือไม่ รวม Manual Trade และ EA ตัวอื่นหรือไม่ และหลังแตะเกณฑ์จะปิด Position หรือหยุดเฉพาะออเดอร์ใหม่

สารบัญ

  • Daily Loss Limit ช่วยอะไร
  • นิยามที่ต้องเขียนให้ครบ
  • เวลารีเซ็ตสำคัญอย่างไร
  • ลำดับการทำงานเมื่อแตะ Limit
  • วิธีกำหนดเกณฑ์จากข้อมูล
  • Checklist ทดสอบก่อนใช้จริง

ทำไม EA ต้องมี Limit ระดับวัน

Stop Loss รายออเดอร์ควบคุมความเสียหายของ Trade หนึ่ง แต่ไม่ได้จำกัดจำนวนครั้งที่ EA สามารถเปิดใหม่ในวันเดียว หากตลาดอยู่ในภาวะไม่เหมาะ ระบบอาจโดน Stop หลายครั้งติดต่อกัน ขณะที่หลาย EA อาจสร้าง Exposure ทิศทางเดียวกันโดยผู้ใช้ไม่ทันสังเกต

Daily Loss Limit จึงเป็น Circuit Breaker ระหว่าง Stop ราย Trade กับ Equity Stop ระดับบัญชี ช่วยตัดวงจร “แพ้แล้วเปิดใหม่ตามสัญญาณเดิม” และกันพื้นที่ของ Risk Budget สำหรับวันถัดไป อย่างไรก็ตาม Limit ไม่ได้ทำให้ Strategy ดีขึ้น และไม่ควรถูกตั้งกว้างเพื่อให้ Backtest ดูผ่านง่าย

คำจำกัดความที่ต้องระบุ

หัวข้อ ตัวเลือกที่ต้องตัดสินใจ
Reference Balance หรือ Equity ณ เวลาเริ่มวัน, High-water Mark หรือค่าคงที่
P/L ที่นับ Realized อย่างเดียว หรือ Realized รวม Floating, Commission และ Swap
Scope ทั้งบัญชี, Magic Number, Strategy, Symbol หรือกลุ่ม Symbol
Threshold จำนวนเงิน เปอร์เซ็นต์ของฐาน หรือหน่วย R
Action หยุดเปิดใหม่, ยกเลิก Pending, ปิดบางส่วน หรือปิดทั้งหมด
Reset เวลาและเขตเวลาที่เริ่มวันใหม่ รวมวันหยุดและ DST

หากนับเฉพาะ Closed P/L ระบบอาจยังถือ Floating Loss ขนาดใหญ่แต่แสดงว่ายังไม่แตะ Limit หากนับ Equity การแกว่งชั่วคราวอาจ Trigger ได้ก่อน Position ปิด ทั้งสองวิธีมี Trade-off จึงต้องเลือกตามลักษณะ Strategy และทดสอบจากข้อมูลระดับที่ละเอียดพอ

“หนึ่งวัน” ต้องอิงเวลาใด

เวลาเครื่องผู้ใช้ เวลา VPS เวลา Server ของ Broker และเวลาไทยอาจไม่ตรงกัน ฟังก์ชันเวลาของ MQL5 ยังแยก TimeLocal, TimeTradeServer และ TimeGMT หาก Logic ใช้คนละฐานกับรายงาน ผลขาดทุนอาจถูกแบ่งข้ามวันผิด และการเปลี่ยน Daylight Saving Time อาจเลื่อนเวลา Server

แนวทางที่ตรวจสอบง่ายคือ:

  • เลือกเขตเวลาหลักหนึ่งค่า เช่น Broker Server Time
  • บันทึกค่า Reference พร้อม Timestamp ตอนเริ่มวัน
  • ระบุว่าช่วง Weekend/Market Closed รีเซ็ตอย่างไร
  • ทดสอบวันที่ Server เปลี่ยน Offset และสิ้นเดือน
  • แสดง Current Daily P/L, Threshold และเวลา Reset ถัดไปบน Dashboard/Log

อย่ารีเซ็ต Limit เพียงเพราะ Restart Terminal เพราะผู้ใช้อาจเปิดระบบใหม่แล้วได้ Risk Budget ซ้ำในวันเดียว State ควรถูกเก็บอย่างคงทนและตรวจสอบกับ Account History เมื่อเริ่มทำงาน

ลำดับเมื่อแตะ Daily Loss Limit

  1. Lock Entry: ตั้งสถานะห้ามส่งคำสั่งเปิดใหม่ก่อน เพื่อไม่ให้ Signal Loop เพิ่ม Exposure ระหว่างปิด
  2. Cancel Pending: ยกเลิก Order ที่ระบบเป็นเจ้าของตาม Scope
  3. Manage Open Positions: ทำตามนโยบายที่กำหนด เช่น คง Stop เดิมหรือปิด Position โดยต้องรองรับคำสั่งล้มเหลว
  4. Persist State: บันทึกว่า Limit ถูกใช้แล้วจนถึงรอบ Reset
  5. Notify and Log: เก็บ Reference, Current Equity, Deal, Error และเหตุผล

ควรป้องกัน Race Condition จากหลาย EA บัญชีเดียวกัน เช่น EA แต่ละ Chart อ่านสถานะพร้อมกันและส่งคำสั่งก่อนเห็น Lock กลาง หาก Limit เป็นระดับบัญชี ควรมี State/Controller กลางที่ทุก Instance ใช้ร่วมกัน

กำหนด Daily Limit จากข้อมูล ไม่ใช่ความรู้สึก

ไม่มีเปอร์เซ็นต์มาตรฐานที่เหมาะกับทุกระบบ เพราะขึ้นกับ Risk per Trade, Trade Frequency, ความสัมพันธ์ของ Position และ Drawdown ที่ผู้ใช้รับได้ วิธีออกแบบควรเริ่มจาก Risk Budget ระดับบัญชีแล้วแบ่งลงมา:

  1. กำหนด Maximum Drawdown/Ruin Threshold ที่รับไม่ได้
  2. สำรวจ Distribution ของ Daily Return และ Worst Day จาก Backtest ที่รวมต้นทุน
  3. ทำ Stress Test โดยเพิ่ม Loss Streak, Spread และ Slippage
  4. ตรวจว่า Limit ตัดวันปกติบ่อยเกินไปหรือปล่อย Tail Event กว้างเกินไป
  5. ทดสอบ Out-of-sample/Forward และประเมินผลต่อ Expectancy
  6. กำหนดเกณฑ์ Review แยกจากเกณฑ์ Resume

Limit ที่แคบมากอาจหยุดระบบในความผันผวนปกติและทำให้พลาด Recovery ส่วน Limit ที่กว้างมากไม่มีคุณค่าเชิงควบคุม ต้องประเมินเป็นส่วนหนึ่งของ Strategy ไม่ใช่เพิ่มหลังเห็นผลลัพธ์ที่ไม่ชอบ

อ่านกรอบที่เกี่ยวข้องได้ที่ Risk per Trade, Risk of Ruin และ Equity Stop

Checklist ทดสอบ

  • Closed P/L และ Floating P/L ถูกนับตามนิยามหรือไม่
  • Commission, Swap, Credit, Deposit และ Withdrawal ถูกจัดการอย่างไร
  • Magic Number/Symbol Scope แยกออเดอร์ถูกต้องหรือไม่
  • การเปิดหลาย Chart พร้อมกันทำให้ Limit ซ้ำหรือไม่
  • Restart Terminal/VPS แล้วสถานะยังอยู่หรือไม่
  • เวลา Server เปลี่ยนหรือข้ามวันแล้ว Reference ถูกต้องหรือไม่
  • คำสั่งปิดถูก Reject/Partial Fill แล้วระบบ Retry อย่างปลอดภัยหรือไม่
  • หลัง Reset ระบบตรวจสาเหตุก่อน Resume หรือไม่

สรุป: Daily Loss Limit ที่ใช้ได้จริงต้องตอบให้ครบว่า “นับอะไร จากฐานไหน ช่วงเวลาใด ครอบคลุมออเดอร์ใด และทำอะไรเมื่อแตะเกณฑ์” เมื่อตรรกะครบจึงค่อยเลือก Threshold จากข้อมูลและ Stress Test

คำเตือนความเสี่ยง: Limit เป็นกลไกควบคุม ไม่รับประกันว่าคำสั่งจะปิดที่ Threshold โดยเฉพาะช่วง Gap, Slippage, สภาพคล่องต่ำ หรือระบบเชื่อมต่อขัดข้อง การเทรดแบบใช้ Leverage มีความเสี่ยงสูง โปรดทดสอบและกำหนดความเสี่ยงให้เหมาะกับตนเอง อ่าน คำเตือนความเสี่ยงฉบับเต็ม
