Allow DLL imports คือตัวเลือกที่อนุญาตให้โปรแกรมบนแพลตฟอร์มเรียกใช้ไลบรารีภายนอกของระบบปฏิบัติการได้ คู่มือเขียนคำเตือนไว้ในชื่อช่องเองว่า potentially dangerous, enable only for trusted applications และแนะนำให้ปิดการนำเข้าไว้เมื่อทำงานกับ EA ที่ไม่รู้ที่มา เพราะเมื่อเปิดแล้วไลบรารีเหล่านั้นใช้งานได้โดยไม่มีข้อจำกัด

บทความนี้ไม่ได้บอกว่า EA ทุกตัวที่ขอให้เปิดช่องนี้มีเจตนาร้าย เพราะมีเหตุผลทางเทคนิคที่สมเหตุสมผลอยู่จริง สิ่งที่บทความนี้ทำคืออธิบายว่าช่องนี้เปลี่ยนอะไร ทำไมบางคนขอ และที่สำคัญที่สุดคือวิธีตรวจด้วยตัวเองว่าโปรแกรมตัวนั้นต้องใช้จริงหรือไม่ โดยไม่ต้องเชื่อคำบอก สัญญาณเตือนที่ควรจำก่อนจ่ายเงินให้ใครอยู่ที่ สัญญาณเตือน EA หลอกลวงก่อนเสียเงิน

Allow DLL imports คืออะไรตามคู่มือจริง

DLL คือไฟล์ไลบรารีของระบบปฏิบัติการที่โปรแกรมอื่นเรียกใช้ฟังก์ชันข้างในได้ คู่มือการตั้งค่าของแพลตฟอร์มอธิบายช่องนี้ว่าโปรแกรมที่เขียนด้วยภาษาของแพลตฟอร์มสามารถใช้ DLL เพื่อขยายความสามารถได้ และตัวเลือกนี้เป็นตัวกำหนดค่าเริ่มต้นของพารามิเตอร์ Allow DLL imports ที่ใช้ตอนเริ่มโปรแกรม พร้อมปิดท้ายว่า "It is recommended to disable import when working with unknown Expert Advisors" คือแนะนำให้ปิดเมื่อทำงานกับ EA ที่ไม่รู้ที่มา

หน้าช่วยเหลือเรื่อง EA อธิบายผลของการติ๊กไว้ชัดกว่านั้น โดยระบุว่าถ้าเปิดตัวเลือกนี้ ไลบรารีเหล่านั้น "can be used without any restrictions" คือใช้งานได้โดยไม่มีข้อจำกัด และถ้าโปรแกรมใช้ DLL แต่การนำเข้าถูกห้ามอยู่ ปุ่ม OK จะไม่แสดงในหน้าต่างเริ่มโปรแกรม หน้าเดียวกันยังเขียนประโยคที่ควรอ่านซ้ำว่าอย่าเปิดตัวเลือกนี้ถ้าคุณไม่มั่นใจว่าการเปิดโปรแกรมนั้นปลอดภัย เพราะโปรแกรมที่ได้มาจากแหล่งที่ไม่รู้จักอาจก่อความเสียหายผ่านการใช้ DLL ของบุคคลที่สาม

เหตุที่คำเตือนแรงขนาดนี้เกี่ยวกับโครงสร้างความปลอดภัยของภาษาเอง เอกสารอ้างอิงของภาษาระบุว่า "For security reasons, work with files is strictly controlled in the MQL5 language" และกำหนดว่าไฟล์ที่โปรแกรมทำงานด้วยอยู่นอกกรอบที่กำหนดไว้ไม่ได้ โดยใช้คำว่า "Work with files from other directories is prohibited" กรอบนี้คือสิ่งที่กันไม่ให้โปรแกรมไปยุ่งกับไฟล์ส่วนอื่นของเครื่อง ส่วนไลบรารีภายนอกไม่ได้อยู่ในกรอบเดียวกัน เพราะเอกสารเรื่องการนำเข้าฟังก์ชันระบุว่าไลบรารีของระบบถูกโหลดตามกฎของระบบปฏิบัติการ

ทำไมผู้พัฒนาบางคนขอให้เปิด

เหตุผลที่พบบ่อยมีสี่ข้อ และสามข้อแรกเป็นเหตุผลที่อธิบายได้

ข้อแรกคือการทำสิ่งที่ภาษาของแพลตฟอร์มทำเองไม่ได้หรือทำได้ไม่ดี เช่นการคำนวณหนัก ๆ ที่เขียนไว้ในไลบรารีภายนอกอยู่แล้ว หรือการเชื่อมต่อกับโปรแกรมอื่นบนเครื่องเดียวกัน ข้อที่สองคือการส่งข้อมูลออกไปนอกเครื่อง เช่นส่งสถานะพอร์ตไปแดชบอร์ดหรือระบบแจ้งเตือนของผู้พัฒนาเอง ข้อที่สามคือการอ่านหรือเขียนไฟล์นอกกรอบที่ภาษากำหนด ซึ่งโดยปกติทำไม่ได้

ข้อที่สี่คือการตรวจไลเซนส์ และเป็นข้อที่ควรถามมากที่สุด เพราะการตรวจว่าผู้ใช้จ่ายเงินแล้วหรือยังมักต้องติดต่อเซิร์ฟเวอร์ของผู้ขาย ซึ่งทำได้ทั้งผ่านไลบรารีภายนอกและผ่านความสามารถส่งคำขอไปเว็บที่มีอยู่ในภาษาแล้ว ถ้าเหตุผลที่ขอให้เปิดช่องนี้คือการตรวจไลเซนส์ ควรถามต่อว่าทำไมไม่ใช้ทางที่แคบกว่าซึ่งคุณกำหนดปลายทางได้เอง

ส่วนคำตอบที่ไม่ควรรับคือ "มันต้องเปิด ไม่งั้นใช้ไม่ได้" โดยไม่มีคำอธิบายว่าใช้ไปทำอะไร เพราะคำขอนี้คือการขอให้คุณถอดกลไกที่ผู้ผลิตแพลตฟอร์มใส่ไว้ให้ ไม่ใช่ขั้นตอนติดตั้งตามปกติ และข้อดีคือคุณตรวจเองได้ว่ามันต้องใช้จริงไหม ซึ่งอยู่ในหัวข้อถัดไป

เปิดแล้วโปรแกรมทำอะไรได้เพิ่ม

สิ่งที่เปลี่ยนไม่ใช่ความสามารถของ EA ตัวนั้นอย่างเดียว แต่เป็นขอบเขตที่มันทำงานอยู่ เอกสารเรื่องการนำเข้าฟังก์ชันอธิบายว่าแพลตฟอร์มใช้การผูกแบบล่วงหน้า คือถ้าโปรแกรมมีการเรียกฟังก์ชันที่นำเข้ามา โมดูลที่เกี่ยวข้องจะถูกโหลดตอนโหลดโปรแกรม และระบุว่าไลบรารีของภาษาและ DLL ทำงานอยู่ในเธรดของโมดูลที่เรียกมัน แปลว่าโค้ดในไลบรารีภายนอกไม่ได้ทำงานแยกห้องจาก EA

ข้อที่คนมักไม่รู้คือลำดับการค้นหาไฟล์ เอกสารระบุว่าไลบรารีของระบบถูกโหลดตามกฎของระบบปฏิบัติการ และถ้ายังไม่ถูกโหลด จะค้นหาตามลำดับ คือโฟลเดอร์ที่โมดูลซึ่งนำเข้า DLL ถูกเริ่มจาก ตามด้วยโฟลเดอร์ไลบรารีในโฟลเดอร์ข้อมูลของแพลตฟอร์ม โฟลเดอร์ที่แพลตฟอร์มถูกเริ่มจาก โฟลเดอร์ของระบบ โฟลเดอร์ของวินโดวส์ โฟลเดอร์ปัจจุบัน และโฟลเดอร์ที่อยู่ในตัวแปร PATH ของระบบ ลำดับนี้สำคัญเพราะไฟล์ที่ถูกโหลดจริงอาจไม่ใช่ไฟล์ที่คุณคิดว่าวางไว้ และเอกสารยังระบุว่าถ้า DLL ตัวหนึ่งต้องใช้ DLL อีกตัวในการทำงาน ตัวแรกจะโหลดไม่ได้เลยถ้าไม่มีตัวที่สอง

ตัวเลือก อนุญาตให้ทำอะไร สิ่งที่คู่มือระบุไว้
Allow DLL imports เรียกใช้ไลบรารีภายนอกของระบบปฏิบัติการ ชื่อช่องมีคำว่า potentially dangerous, enable only for trusted applications และเมื่อเปิดแล้วไลบรารีใช้งานได้โดยไม่มีข้อจำกัด
Allow WebRequest for listed URL ส่งและรับข้อมูลกับเว็บเฉพาะที่อยู่ในรายการที่คุณพิมพ์เอง ปิดเป็นค่าเริ่มต้นด้วยเหตุผลด้านความปลอดภัย และต้องระบุที่อยู่ของเว็บที่ไว้ใจได้เองทีละรายการ
การเทรดอัตโนมัติผ่าน Python API ภายนอก ให้สคริปต์ภายนอกส่งคำสั่งเทรดได้ ปิดเป็นค่าเริ่มต้นด้วยเหตุผลด้านความปลอดภัย ต้องติ๊กเปิดเองอย่างชัดแจ้ง

ความต่างที่สำคัญของสามช่องนี้คือขอบเขต ช่องกลางให้คุณกำหนดปลายทางได้เองทีละรายการ จึงจำกัดได้ว่าโปรแกรมคุยกับใครได้ ส่วนช่องแรกไม่มีรายการให้กำหนด เพราะเมื่อเปิดแล้วคือเปิดทั้งความสามารถ

ตัวเลือกในหน้าตั้งค่าของแพลตฟอร์มเป็นเพียง "ค่าเริ่มต้น" ที่ใช้ตอนเริ่มโปรแกรม ไม่ใช่สวิตช์เดียวที่ควบคุมทุกอย่าง คู่มือระบุว่าค่านี้ถูกใช้เป็นค่าเริ่มต้นของพารามิเตอร์เดียวกันในหน้าต่างเริ่มโปรแกรมแต่ละตัว ดังนั้นวิธีที่ควรทำคือปิดไว้ที่ค่าเริ่มต้นเสมอ แล้วเปิดเฉพาะหน้าต่างของโปรแกรมที่คุณตรวจแล้วและไว้ใจแล้วเท่านั้น ไม่ใช่เปิดทิ้งไว้ทั้งแพลตฟอร์มเพื่อความสะดวก

ข้อสังเกตจากกฎของร้านค้าในแพลตฟอร์ม

มีข้อเท็จจริงหนึ่งที่ช่วยจัดบริบทได้ทันที กฎการใช้บริการตลาดของแพลตฟอร์มระบุว่าสินค้าที่ขายผ่านช่องทางนั้น "must not contain calls to any DLL, including Microsoft Windows system libraries" คือต้องไม่มีการเรียก DLL ใด ๆ เลย รวมถึงไลบรารีของระบบปฏิบัติการด้วย

ข้อนี้แปลเป็นภาษาคนได้สองอย่าง อย่างแรกคือ EA ที่ต้องให้คุณเปิดช่องนี้ย่อมไม่ได้ขายผ่านช่องทางที่มีกฎชุดนั้นบังคับอยู่ ไม่ว่าคนขายจะอ้างอะไร อย่างที่สองคือมีผู้พัฒนาจำนวนมากที่เขียน EA ซึ่งทำงานได้ครบโดยไม่ต้องเรียก DLL เลย เพราะถ้าเรียกแล้วจะขายในช่องทางนั้นไม่ได้ตั้งแต่ต้น ดังนั้นคำกล่าวที่ว่าระบบเทรดจริงจังต้องใช้ DLL ไม่เป็นความจริงในทางปฏิบัติ

กฎชุดเดียวกันยังระบุว่าผู้ขายต้องไม่ฝังระบบขาย ระบบบัญชี ระบบควบคุมไลเซนส์ และระบบจัดการอัปเดตของเจ้าอื่นลงในสินค้า โดยวงเล็บไว้ว่ารวมถึงระบบที่ใช้ความสามารถส่งคำขอไปเว็บ ข้อนี้ตอบคำถามเรื่องการตรวจไลเซนส์ได้ตรง คือในช่องทางที่มีกฎบังคับ การตรวจไลเซนส์ถูกทำโดยระบบของแพลตฟอร์มเอง ไม่ใช่โดยการให้ผู้ใช้เปิดสิทธิ์เพิ่ม

วิธีทดสอบว่าจำเป็นจริงไหม

ข่าวดีคือเรื่องนี้ตรวจได้เองในเวลาไม่กี่นาที และไม่ต้องใช้ความรู้โปรแกรมมิ่งเลย ทำตามสามขั้นนี้บนบัญชีเดโม่

  1. ดูแท็บ Dependencies ในหน้าต่างเริ่มโปรแกรม คู่มือระบุว่าแท็บนี้จะปรากฏขึ้นถ้า EA มีการนำเข้าฟังก์ชันจากไฟล์ EX5 หรือ DLL อื่น และระบุว่าไฟล์ที่ถูกใช้จะแสดงเป็นรายการแบบต้นไม้ โดยไอคอนสีเขียวหมายถึงการเรียกฟังก์ชันจากโปรแกรมที่เขียนด้วยภาษาของแพลตฟอร์ม และไอคอนสีแดงหมายถึงการเรียกฟังก์ชันที่อยู่ใน DLL ถ้าไม่มีแท็บนี้เลย แปลว่าโปรแกรมไม่ได้นำเข้าอะไรจากภายนอก และคำบอกที่ว่าต้องเปิดช่องนี้ไม่ตรงกับสิ่งที่ไฟล์ทำ
  2. ลองเปิดโปรแกรมโดยยังไม่ติ๊กช่องนั้น คู่มือระบุว่าถ้าโปรแกรมใช้ DLL แต่การนำเข้าถูกห้ามอยู่ ปุ่ม OK จะไม่แสดงในหน้าต่างเริ่มโปรแกรม นี่คือการยืนยันอีกชั้นว่ามันเรียก DLL จริงหรือไม่ โดยที่คุณยังไม่ได้ให้สิทธิ์อะไรไป
  3. อ่านบันทึกของแพลตฟอร์ม เอกสารเรื่องการนำเข้าฟังก์ชันระบุว่าถ้าไลบรารีโหลดไม่ได้ หรือมีการห้ามใช้ DLL หรือหาฟังก์ชันที่นำเข้าไม่พบ EA จะหยุดทำงานพร้อมข้อความ "Expert Advisor stopped" ในบันทึก และจะไม่ทำงานอีกจนกว่าจะถูกเริ่มต้นใหม่ ซึ่งทำได้ด้วยการคอมไพล์ใหม่หรือเปิดหน้าต่างคุณสมบัติแล้วกด OK ดังนั้นถ้าคุณปล่อยให้มันรันโดยไม่เปิดช่องนั้นแล้วมันยังทำงานต่อไปตามปกติ คำตอบคือมันไม่ต้องใช้ วิธีอ่านบันทึกทีละแท็บอยู่ที่ อ่านแท็บ Experts กับ Journal ใน MT5 ยังไงตอน EA มีปัญหา

ขั้นตอนทั้งสามข้อนี้ควรทำก่อนแนบโปรแกรมเข้ากราฟบัญชีจริงทุกครั้ง และควรเข้าใจความต่างระหว่างไฟล์ที่คอมไพล์แล้วกับไฟล์ซอร์สก่อน เพราะไฟล์ที่นำเข้า DLL อ่านตรรกะข้างในไม่ได้ถ้าไม่มีซอร์สโค้ด รายละเอียดอยู่ที่ ไฟล์ EX5 กับ MQ5 ต่างกันยังไง ต้องวางไว้ตรงไหน และลำดับการเปิดใช้งานที่ถูกต้องอยู่ที่ เปิด AutoTrading ใน MT5 ยังไงให้ EA เริ่มทำงาน

ทางเลือกที่ปลอดภัยกว่า

ถ้าตรวจแล้วพบว่าโปรแกรมนั้นเรียก DLL จริงและคุณยังต้องการใช้มัน มีทางเลือกที่ลดความเสียหายที่แย่ที่สุดได้

ขอรายการพึ่งพาและคำอธิบายทีละไฟล์ แท็บ Dependencies แสดงชื่อไฟล์ให้คุณอยู่แล้ว ให้ถามว่าแต่ละไฟล์ทำหน้าที่อะไร ถ้าคำตอบตรงกับสิ่งที่โปรแกรมควรทำก็เป็นสัญญาณที่ดี ถ้าตอบไม่ได้หรือเลี่ยงตอบ ให้หยุดตรงนั้น

ถามหาทางที่แคบกว่า ถ้าเหตุผลคือการส่งข้อมูลออกไปนอกเครื่องหรือการตรวจไลเซนส์ ให้ถามว่าทำผ่านความสามารถส่งคำขอไปเว็บได้หรือไม่ เพราะคู่มือระบุว่าทางนั้นคุณต้องพิมพ์ที่อยู่ของเว็บที่ไว้ใจได้เข้าไปเอง ซึ่งแปลว่าคุณเห็นและจำกัดปลายทางได้ ต่างจากการเปิดการนำเข้าไลบรารีที่คู่มือระบุว่าใช้งานได้โดยไม่มีข้อจำกัด

แยกเครื่องและเริ่มจากเดโม่ ถ้าจะเปิดสิทธิ์นี้ ให้เปิดบนเครื่องหรือเซิร์ฟเวอร์ที่ไม่มีอย่างอื่นสำคัญอยู่ ไม่ใช่เครื่องที่ใช้ทำงานทุกวัน และรันบนบัญชีเดโม่ให้ผ่านหลายสภาพตลาดก่อน การตั้งรหัสผ่าน การอัปเดต และการสำรองข้อมูลของเซิร์ฟเวอร์ที่ใช้รัน อยู่ที่ วิธีรักษาความปลอดภัย VPS สำหรับ MT5

เปิดเฉพาะหน้าต่างของโปรแกรมนั้น อย่าเปิดที่หน้าตั้งค่ารวม เพราะคู่มือระบุว่าค่านั้นเป็นเพียงค่าเริ่มต้นที่ใช้ตอนเริ่มโปรแกรมทุกตัว การเปิดทิ้งไว้จึงเท่ากับให้สิทธิ์ล่วงหน้ากับทุกอย่างที่คุณจะเปิดในอนาคต และแยกอีกเรื่องให้ชัด คือการติดตั้งและรัน EA บนเครื่องของคุณเองไม่ต้องใช้รหัสผ่านบัญชีเทรดของใครเลย คำขอรหัสผ่าน คำขอให้ลงโปรแกรมควบคุมเครื่องระยะไกล หรือคำขอไฟล์ตั้งค่าบัญชี ไม่ใช่ขั้นตอนของการติดตั้ง EA ถ้าต้องการระบบที่ติดตั้งแล้วใช้ได้โดยไม่ต้องเปิดสิทธิ์เพิ่ม ขั้นตอนเริ่มใช้งานของเราอยู่ที่ หน้าเริ่มใช้งานและดาวน์โหลด

สรุป

สรุป: Allow DLL imports คือตัวเลือกที่อนุญาตให้โปรแกรมบนแพลตฟอร์มเรียกใช้ไลบรารีภายนอกของระบบปฏิบัติการ คู่มือเขียนคำเตือนไว้ในชื่อช่องเองว่า potentially dangerous, enable only for trusted applications แนะนำให้ปิดไว้เมื่อทำงานกับ EA ที่ไม่รู้ที่มา และระบุว่าเมื่อเปิดแล้วไลบรารีเหล่านั้นใช้งานได้โดยไม่มีข้อจำกัด เหตุผลที่ผู้พัฒนาขอให้เปิดมีทั้งที่อธิบายได้ เช่นการคำนวณหนัก การเชื่อมต่อกับโปรแกรมอื่น และการเขียนไฟล์นอกกรอบที่ภาษากำหนด และที่ควรถามต่อ คือการตรวจไลเซนส์ ข้อเท็จจริงที่ช่วยจัดบริบทคือกฎของร้านค้าในแพลตฟอร์มระบุว่าสินค้าที่ขายในช่องทางนั้นต้องไม่มีการเรียก DLL ใด ๆ เลยรวมถึงไลบรารีของระบบ แปลว่า EA ที่ต้องให้เปิดช่องนี้อยู่นอกกรอบกฎชุดนั้น และแปลว่าระบบที่ทำงานครบโดยไม่ใช้ DLL มีอยู่จริงจำนวนมาก วิธีตรวจว่าจำเป็นจริงไหมทำได้สามขั้นบนบัญชีเดโม่ คือดูแท็บ Dependencies ซึ่งจะปรากฏเมื่อมีการนำเข้าฟังก์ชันและแสดงไอคอนสีแดงสำหรับการเรียก DLL ลองเปิดโดยยังไม่ติ๊กแล้วดูว่าปุ่ม OK แสดงหรือไม่ และอ่านบันทึกว่ามีข้อความ Expert Advisor stopped หรือไม่ ถ้ามันยังรันต่อได้โดยไม่เปิดช่องนั้น คำตอบคือไม่จำเป็น ทางที่ปลอดภัยกว่าคือขอรายการพึ่งพาทีละไฟล์ ถามหาทางที่กำหนดปลายทางได้เอง แยกเครื่องและเริ่มจากเดโม่ และเปิดสิทธิ์เฉพาะหน้าต่างของโปรแกรมที่ตรวจแล้วเท่านั้น

คำเตือนความเสี่ยง: การเทรดด้วยมาร์จิ้นมีความเสี่ยงสูงและอาจทำให้สูญเงินลงทุนทั้งจำนวน การตรวจสิทธิ์ที่โปรแกรมขอช่วยลดความเสี่ยงด้านความปลอดภัยของเครื่องเท่านั้น ไม่ได้ลดความเสี่ยงของการเทรดและไม่ได้รับประกันผลกำไร คู่มือของแพลตฟอร์มระบุเองว่าโปรแกรมที่ได้มาจากแหล่งที่ไม่รู้จักอาจก่อความเสียหายผ่านการใช้ DLL ของบุคคลที่สาม จึงไม่ควรเปิดสิทธิ์นี้ให้ไฟล์ที่ไม่รู้ที่มา บทความนี้เป็นข้อมูลทั่วไป ไม่ใช่คำแนะนำการลงทุน และไม่ได้กล่าวถึงบุคคล กลุ่ม หรือผู้ให้บริการรายใดเป็นการเฉพาะ ใช้เฉพาะเงินที่พร้อมรับความเสียหายและไม่มีกำหนดต้องใช้ อ่าน คำเตือนความเสี่ยงฉบับเต็ม

คำถามที่พบบ่อย

allow dll imports ไม่เปิดแล้ว EA จะใช้ไม่ได้จริงไหม

ขึ้นกับว่าไฟล์นั้นนำเข้าฟังก์ชันจาก DLL จริงหรือไม่ ซึ่งตรวจได้เองจากแท็บ Dependencies ในหน้าต่างเริ่มโปรแกรม ถ้าไม่มีแท็บนี้แปลว่าไม่ได้นำเข้าอะไร และถ้ามีการใช้ DLL แต่การนำเข้าถูกห้ามอยู่ คู่มือระบุว่าปุ่ม OK จะไม่แสดงในหน้าต่างเริ่มโปรแกรม

เปิด Allow DLL imports อันตรายยังไง

คู่มือระบุว่าเมื่อเปิดแล้วไลบรารีภายนอกใช้งานได้โดยไม่มีข้อจำกัด และเตือนว่าโปรแกรมจากแหล่งที่ไม่รู้จักอาจก่อความเสียหายผ่านการใช้ DLL ของบุคคลที่สาม ขณะที่กรอบจำกัดการเข้าถึงไฟล์ของภาษาใช้กับโค้ดที่เขียนด้วยภาษานั้น ไม่ได้ครอบคลุมไลบรารีของระบบที่ถูกโหลดตามกฎของระบบปฏิบัติการ

EA ที่ขายในร้านค้าของแพลตฟอร์มใช้ DLL ได้ไหม

ไม่ได้ กฎการใช้บริการตลาดระบุว่าสินค้าต้องไม่มีการเรียก DLL ใด ๆ รวมถึงไลบรารีของระบบปฏิบัติการ ดังนั้นถ้ามีคนอ้างว่าสินค้าจากช่องทางนั้นต้องให้เปิดช่องนี้ ข้อมูลสองอย่างนี้ขัดกันอยู่

ต่างกับช่อง Allow WebRequest ยังไง

ขอบเขตต่างกัน ช่อง WebRequest คู่มือระบุว่าปิดเป็นค่าเริ่มต้นด้วยเหตุผลด้านความปลอดภัย และต้องพิมพ์ที่อยู่ของเว็บที่ไว้ใจได้เข้าไปเองทีละรายการ จึงจำกัดปลายทางได้ ส่วนการนำเข้าไลบรารีไม่มีรายการให้กำหนด เพราะเมื่อเปิดแล้วใช้งานได้โดยไม่มีข้อจำกัด

เปิดไว้ที่หน้าตั้งค่ารวมเลยได้ไหม จะสะดวกกว่า

ไม่ควร คู่มือระบุว่าค่าในหน้าตั้งค่าเป็นเพียงค่าเริ่มต้นของพารามิเตอร์เดียวกันที่ใช้ตอนเริ่มโปรแกรมทุกตัว การเปิดทิ้งไว้จึงเท่ากับให้สิทธิ์ล่วงหน้ากับทุกโปรแกรมที่คุณจะเปิดในอนาคต วิธีที่ถูกคือปิดไว้แล้วเปิดเฉพาะหน้าต่างของโปรแกรมที่ตรวจแล้ว
