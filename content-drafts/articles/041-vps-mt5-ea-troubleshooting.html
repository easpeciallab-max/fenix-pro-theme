เมื่อ VPS หลุด, MT5 ค้าง หรือ EA หยุดทำงาน การ Restart ทุกอย่างทันทีอาจทำให้ระบบกลับมา แต่ลบหลักฐานและไม่แก้ต้นเหตุ วิธีที่ดีกว่าคือแยกชั้น Power, Windows Session, Process, Resource, Network, Account, Platform และ EA แล้วเก็บเวลา/Log ก่อนเปลี่ยนแปลง

หากมี Open Position ให้ทำตาม Emergency/Risk Runbook ก่อนงานวิเคราะห์ ความสำคัญแรกคือทราบ Exposure และควบคุมบัญชีผ่านช่องทางที่ได้รับอนุญาต ไม่ทดลองแก้หลายอย่างพร้อมกันบน Production

สารบัญ

  • Triage 5 นาทีแรก
  • ตรวจทีละชั้น
  • อ่าน Experts และ Journal
  • อาการยอดนิยมและสาเหตุ
  • Restart อย่างมีหลักฐาน
  • ป้องกันเกิดซ้ำ

Triage: หยุดความเสียหายและบันทึกเวลา

  1. บันทึกเวลาไทย เวลา VPS และเวลา Broker Server
  2. ตรวจ Open Position/Pending/Equity/Margin ผ่านช่องทางที่เชื่อถือได้
  3. หากต้องหยุด Entry ใช้วิธีที่ Runbook กำหนด ไม่ลบ EA โดยไม่เก็บ State
  4. ตรวจหน้า Status ของ VPS Provider และ Broker
  5. เก็บ Screenshot, Error, Process List และ Resource Metric
  6. ระบุการเปลี่ยนแปลงล่าสุด เช่น Update, Preset, Password หรือ Terminal ใหม่

แยก “เข้า RDP ไม่ได้” ออกจาก “VPS ล่ม” เพราะ RDP Service/Firewall อาจมีปัญหาแต่ MT5 ยังทำงาน ขณะเดียวกัน RDP เข้าได้ไม่ได้แปลว่า EA พร้อมเทรด ต้องตรวจแต่ละชั้น

ตรวจจากโครงสร้างพื้นฐานขึ้นไป

1. Power และ Provider

  • Instance Running, Stopped, Rebooting หรือ Suspended
  • มี Maintenance/Incident หรือ Billing Hold หรือไม่
  • Console/Serial Console เข้าได้หรือไม่
  • Uptime ของ Windows เปลี่ยนหรือไม่

2. Windows Session

  • User ถูก Sign out หรือเพียง Disconnected
  • มี Session ซ้ำทำให้เปิด MT5 สองชุดหรือไม่
  • Scheduled Task/Startup ทำงานหลัง Boot หรือไม่
  • Event Viewer มี Update, Crash, Disk หรือ Network Event หรือไม่

3. Process และ Resource

  • terminal64.exe อยู่หรือไม่ และ Path ถูก Terminal
  • CPU 100%, Memory Pressure, Disk เต็ม/Queue สูงหรือไม่
  • มี Backtest, Antivirus Scan หรือ Update แย่งทรัพยากรหรือไม่
  • Process Not Responding นานกว่ารอบปกติหรือไม่

4. Network และ Broker

  • VPS ออก Internet/DNS ได้หรือไม่
  • MT5 แสดง No Connection, Invalid Account หรือ Authorization Error
  • ชื่อ Account Server ถูกต้องและ Credential ยังใช้ได้หรือไม่
  • มี Packet Loss/Route เปลี่ยนหรือ Broker Maintenance หรือไม่

5. Platform และ EA

  • AutoTrading/Algo Trading เปิดตามนโยบายหรือไม่
  • EA ยัง Attach กับ Chart และมีชื่อ/สัญลักษณ์สถานะหรือไม่
  • Allow Algo Trading, DLL/WebRequest ตามที่ระบบต้องใช้ถูกต้องหรือไม่
  • Market เปิด Symbol Trade Enabled และมี Tick ใหม่หรือไม่
  • Daily Limit, Equity Stop หรือ License Lock หยุดระบบตามแผนหรือไม่

บทความ EA ไม่ทำงานบน MT5 ช่วยไล่ตรวจระดับ Platform/EA ส่วน No Connection และ Invalid Account เน้นปัญหา Login/Server

Experts และ Journal บอกคนละส่วน

MetaTrader 5 แยก:

  • Experts: ข้อความจาก EA/Indicator เช่น Initialization, Signal, Order และ Error ของ Logic
  • Journal: Platform Start, Network, Authorization, Trade Operation และเหตุการณ์ระบบ

ก่อน Clear หรือ Restart ให้เปิด Context Menu > Open/บันทึกไฟล์ Log ตามวันที่ จด Timestamp และค้นคำ เช่น error, failed, no connection, invalid, disabled แต่ต้องอ่านบรรทัดก่อน-หลัง ไม่ตัด Error Code เดี่ยวออกจากบริบท

ใช้คู่มือ วิธีอ่าน Experts และ Journal Log และส่งเฉพาะข้อมูลที่ไม่เปิดเผย Login/ข้อมูลส่วนตัวให้ Support

จับคู่ “อาการ” กับจุดตรวจ

อาการ จุดตรวจแรก
เข้า RDP ไม่ได้ Provider Status, Power, Console, RDP Service/Firewall
RDP ได้แต่ MT5 หาย Uptime, Session, Task Scheduler, Process Crash
MT5 เปิดแต่ราคาไม่เดิน Market Hours, Connection, Server, Symbol Tick
ราคาเดินแต่ EA ไม่เปิด AutoTrading, EA State, Signal Filter, Risk Lock, Log
EA เปิดซ้ำ Session/Process ซ้ำ, Magic, Chart ซ้ำ, Auto-start Retry
MT5 ช้ามาก CPU, RAM, Disk, Chart/Symbol Count, Tester/Update

“EA ไม่เปิดออเดอร์” อาจเป็นพฤติกรรมถูกต้องเมื่อไม่มี Signal หรือ Risk Limit ทำงาน จึงต้องแยก Not Trading by Design จาก Failure โดยให้ EA Log Reason Code เช่น No Signal, Spread Filter, Session Filter, Limit Locked หรือ Trade Disabled

Restart เมื่อจำเป็นโดยไม่ทำลายข้อมูล

ก่อน Restart:

  1. บันทึก Position/Pending/Risk State
  2. Copy/Archive Log และ Event ที่เกี่ยวข้อง
  3. บันทึก Process/Resource/Network Snapshot
  4. ตรวจว่ามี State File หรือการปิดแบบ Graceful หรือไม่
  5. แจ้งผู้รับผิดชอบและกำหนด Rollback

หลัง Restart ให้ใช้ Checklist จาก Auto-start MT5 หลัง VPS Restart ตรวจ Process Count, Account, Server, EA, Preset, Magic, Connection และ Pending ก่อนเปิด Entry หาก Root Cause ยังไม่ทราบ ให้รัน Risk ลดลงหรือ Demo ตามนโยบาย

เปลี่ยน Incident เป็นระบบป้องกัน

  • สร้าง Monitoring CPU/RAM/Disk/Network/Process/Heartbeat
  • ตั้ง Alert ภายนอก VPS และกำหนดผู้รับผิดชอบ
  • เก็บ Log ตาม Retention และรวม Timestamp/Terminal ID
  • ทำ Change Log ของ Windows, MT5, EA และ Preset
  • กำหนด Maintenance Window และ Reboot Test
  • มี Backup/Restore Test และ VPS Replacement Runbook
  • ทำ Post-incident Review โดยไม่แก้หลายอย่างจนหาสาเหตุไม่ได้

เลือกสเปกและ Headroom ตาม คู่มือเลือก VPS สำหรับ MT5 และวัด Network ตาม Latency/Ping ของ VPS

สรุป: Troubleshooting ที่เร็วไม่ใช่ Restart เร็วที่สุด แต่คือแยกชั้นได้เร็ว เก็บหลักฐานครบ และมี Runbook ควบคุม Exposure ก่อนเปลี่ยนระบบ เมื่อรู้ชั้นที่เสียจึงแก้จุดเดียวและยืนยันผล

คำเตือนความเสี่ยง: ระหว่างระบบขัดข้อง Position อาจยังเคลื่อนไหวและเกิดความเสียหาย VPS/MT5/EA ไม่รับประกันความต่อเนื่อง ผู้ใช้ต้องมี Monitoring และช่องทางจัดการฉุกเฉิน การเทรดมีความเสี่ยงสูง อ่าน คำเตือนความเสี่ยงฉบับเต็ม
