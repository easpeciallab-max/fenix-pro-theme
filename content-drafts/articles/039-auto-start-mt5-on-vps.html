VPS อาจ Restart จาก Windows Update, Maintenance หรือเหตุขัดข้อง หาก MT5 ไม่เปิดกลับ EA จะหยุดรับ Tick และจัดการ Logic ที่ทำงานฝั่ง Terminal การตั้ง Auto Start MT5 จึงควรเป็นส่วนหนึ่งของ Recovery Runbook แต่การเห็นหน้าต่าง Terminal เปิดไม่ได้แปลว่าระบบพร้อมส่งคำสั่งแล้ว

ต้องแยกสองเหตุการณ์: System Startup เกิดเมื่อ Windows Boot และ User Logon เกิดเมื่อบัญชีผู้ใช้เข้าสู่ Session โปรแกรมแบบ Desktop เช่น MT5 อาจต้องทำงานใน User Session ที่เหมาะสม จึงต้องเลือก Trigger, User Account และสิทธิ์ตาม Environment แล้วทดสอบ Reboot จริง

สารบัญ

  • วิธีเปิดอัตโนมัติที่ใช้บ่อย
  • ตั้ง Task Scheduler อย่างเป็นระบบ
  • เปิดหลาย Terminal โดยไม่ชนกัน
  • Startup Guard ของ EA
  • วิธีทดสอบหลัง Reboot
  • สาเหตุที่ Task ทำงานแต่ MT5 ไม่พร้อม

Startup Folder, Run Key และ Task Scheduler

วิธี ข้อดี ข้อจำกัด
Startup Folder ตั้งง่าย เห็น Shortcut ชัด เริ่มเมื่อ User Logon และควบคุม Delay/Retry จำกัด
Run Registry ทำงานเมื่อ User Logon ลำดับเปิดหลายโปรแกรมไม่แน่นอนและดูแลยากกว่า Shortcut
Task Scheduler กำหนด User, Trigger, Delay, Retry และ History ได้ ต้องตั้ง Session/Permission/Path ให้ถูกและทดสอบ UI Application

สำหรับ MT5 หลาย Terminal มักใช้ Task Scheduler เพราะตั้ง Delay แยกและดู Last Run Result ได้ แต่ไม่ควรเลือก “Run whether user is logged on or not” โดยไม่ทดสอบ เพราะ Task อาจอยู่ใน Non-interactive Session และโปรแกรม Desktop/Automation บางแบบทำงานไม่เหมือนตอนผู้ใช้ล็อกอิน

ขั้นตอนวาง Task Scheduler

  1. ยืนยัน Path ของ terminal64.exe และ Shortcut Argument ของ Terminal เป้าหมาย
  2. เปิด Task Scheduler ด้วยสิทธิ์ที่อนุญาตและเลือก Create Task
  3. ตั้งชื่อที่มี Terminal ID เช่น MT5-T01-START
  4. เลือก User Account เดียวกับที่ติดตั้ง/มี Data Folder และ Credential ตามนโยบาย
  5. สร้าง Trigger แบบ At log on สำหรับ User นั้น หรือ At startup ตามวิธีที่ทดสอบผ่าน
  6. ตั้ง Delay เพื่อรอ Network/Service และลด Load Spike
  7. Action เลือก Start a program ใส่ Program, Argument และ Start in Directory ให้ครบ
  8. กำหนด Retry หาก Task ล้มเหลว แต่จำกัดจำนวนครั้งเพื่อป้องกัน Process ซ้ำ
  9. เปิด Task History/Logging และ Export XML เก็บไว้กับ Runbook

Windows ระบุว่า Logon Trigger จะเริ่ม Action เมื่อ User ที่กำหนดเข้าสู่ระบบ ส่วน On-start เริ่มเมื่อระบบ Boot การเลือกต้องสอดคล้องกับวิธีรักษา Session ของ VPS ไม่ควรเปิด Auto Logon แบบไม่มีการควบคุมเพียงเพื่อให้ MT5 เริ่มง่ายขึ้น

หลาย Terminal ต้องเปิดแบบ Staggered

หากเปิดห้า Terminal พร้อมกัน ทุก Process อาจ Sync History, Login และอ่านไฟล์ในเวลาเดียวกัน ทำให้ CPU/Disk/Network พุ่ง ตั้ง Delay เช่น Terminal ถัดไปรอหลังตัวก่อนตามช่วงที่ทีมทดสอบ ไม่ใช้ค่าตายตัวจากเครื่องอื่น

แต่ละ Task ต้องมี:

  • Executable Path เฉพาะ Terminal
  • Argument เช่น /portable หรือ Config ที่ถูกต้อง
  • Working Directory ถูกชุด
  • Terminal ID ในชื่อ Task/Shortcut
  • เงื่อนไข “ห้ามเปิดถ้ามี Process ชุดนี้อยู่แล้ว” หรือ Script Guard

ดูการแยกโฟลเดอร์ที่ วิธีติดตั้ง MT5 หลาย Terminal บน VPS การเปิด executable ผิด Path อาจพาไป Data Folder/Account คนละชุดแม้หน้าตาเหมือนกัน

Startup Guard ก่อน EA เทรด

เมื่อ Terminal เปิด EA อาจได้รับ Tick และสัญญาณทันที ควรมีเงื่อนไข Readiness ก่อน Entry:

  • Account Login และ Server ตรงกับ Allowlist
  • Connection พร้อมและ Symbol Synchronization เสร็จ
  • เวลา Server/Local อยู่ในช่วงสมเหตุสมผล
  • EA Version, Preset, Magic Number และ License ถูกต้อง
  • ไม่มี Position/Order ซ้ำจาก Instance อื่น
  • Daily Loss/Equity Stop State ถูกโหลดกลับ
  • Indicator/History ที่ Logic ต้องใช้มีข้อมูลพอ

ถ้าเงื่อนไขไม่ผ่าน ให้ EA อยู่ใน Safe State: ไม่เปิดออเดอร์ใหม่ แสดงเหตุผลและแจ้งเตือน ไม่ใช้วิธีรอเวลาคงที่อย่างเดียว เพราะ Network/History Sync อาจใช้เวลาต่างกันแต่ละครั้ง

ทดสอบ Reboot แบบ Acceptance Test

  1. เก็บรายการ Position/Pending/State ก่อนทดสอบใน Demo หรือ Maintenance Window
  2. Restart VPS จริง ไม่ทดสอบเพียง Sign out/Disconnect
  3. จับเวลาตั้งแต่ Boot ถึงแต่ละ Terminal เริ่มทำงาน
  4. ตรวจ Task History และ Windows Event Log
  5. ยืนยัน Account, Server, Chart, EA, Magic, Preset ทุก Terminal
  6. ตรวจ Expert/Journal ว่า Connection และ History Sync ไม่มี Error
  7. ยืนยันว่า EA ไม่ส่งออเดอร์ซ้ำจาก State เก่า
  8. Disconnect RDP แล้วกลับมาตรวจ Log/Process ภายหลัง

ทำ Test ซ้ำหลัง Windows/MT5 Update และเมื่อเปลี่ยน Password/User Policy เพราะ Credential ของ Scheduled Task อาจหมดอายุหรือสิทธิ์เปลี่ยน

Task ขึ้น Running/Success แต่ระบบยังไม่พร้อม

  • Task เปิด executable แต่ Process ปิดทันทีเพราะ Path/Permission
  • เปิด MT5 อีก Installation หรือ Data Folder ผิด
  • Task รันใน Session ที่มองไม่เห็นและ EA/UI ทำงานไม่ครบ
  • ไม่มี Network ตอนเริ่ม ทำให้ Login ไม่สำเร็จและไม่มี Retry
  • หลาย Task เปิด Process ซ้ำเพราะ Retry ไม่ตรวจ Instance
  • Password บัญชี Windows เปลี่ยนแต่ Credential ใน Task ยังเก่า
  • Terminal Update แสดง Dialog รอการตอบรับ
  • AutoTrading ปิดหรือ EA ไม่ถูก Attach หลัง Profile เสีย

ตรวจจาก Process Path, Task History, Event Viewer และ Experts/Journal Log ของ MT5 ไม่สรุปจาก Last Run Result เพียงค่าเดียว

Monitoring ที่ควรมีหลังตั้ง Auto-start

Auto-start ที่ไม่มี Monitoring อาจล้มเงียบ ควรตรวจ Heartbeat ของ Terminal/EA, เวลา Tick ล่าสุด, Connection, Process Count และสถานะ AutoTrading พร้อม Alert เมื่อไม่เปลี่ยนตามรอบ ระบบแจ้งเตือนต้องอยู่นอก VPS อย่างน้อยหนึ่งช่องทาง เพื่อให้ยังส่งได้เมื่อเครื่องเป้าหมายล่ม

สรุป: ตั้ง Task ให้เปิด MT5 เป็นงานหนึ่ง แต่ระบบ Production ต้องมี User Session ที่ถูกต้อง ลำดับเปิดหลาย Terminal, Readiness Guard, Persistent State, Monitoring และ Reboot Test จึงจะกลับมาทำงานได้โดยไม่ส่งคำสั่งซ้ำ

คำเตือนความเสี่ยง: Auto-start ไม่รับประกันว่า VPS, MT5 หรือ EA จะกลับมาทำงานสมบูรณ์หลัง Restart ผู้ใช้ต้องตรวจสอบและมีแผนฉุกเฉิน การเทรดด้วย EA มีความเสี่ยงสูง อ่าน คำเตือนความเสี่ยงฉบับเต็ม
