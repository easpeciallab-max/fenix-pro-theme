## 2) เทคนิค SEO

### 2.1 จุดที่ทำดีอยู่แล้ว

- Schema: ธีมยิง Organization + WebSite (ทั้งเว็บ), FAQPage (หน้าแรก), BlogPosting (บทความ) อยู่แล้ว ผ่าน fenix_schema_jsonld() และ single.php และมี guard ปิดอัตโนมัติเมื่อมีปลั๊ก SEO (Yoast/RankMath/SEOPress) ป้องกัน schema ซ้ำ
- Open Graph + Twitter Card + meta description: ครบทุกหน้าผ่าน fenix_open_graph() (รวม article:published_time/modified_time สำหรับบทความ) และมี guard ปิดเมื่อมีปลั๊ก SEO เช่นกัน ไม่เกิดแท็กซ้ำ
- Title tag จัดการโดย WP core (add_theme_support('title-tag')) ถูกต้อง ไม่ hardcode <title>
- Breadcrumb (มองเห็นได้) มีจริงใน single.php และ page.php พร้อม aria-label ภาษาไทย เป็นฐานที่ดีสำหรับต่อยอด BreadcrumbList JSON-LD
- Mobile: มี meta viewport ถูกต้อง, mobile bottom nav, hamburger พร้อม aria-expanded ใน main.js โครงสร้าง responsive พร้อมแล้ว
- Image hygiene พื้นฐานดี: รูปส่วนใหญ่ใส่ alt จาก setting, hero ใช้ loading=eager (ถูกสำหรับ LCP), รูปรองใช้ loading=lazy, โลโก้/รูปหลายจุดมี width/height กัน layout shift
- RSS feed เปิดอยู่ (automatic-feed-links) ใช้ได้ทันทีสำหรับ syndication และ Google ping
- Asset versioning อิง filemtime ของ style.css/main.js ทำให้ cache-busting อัตโนมัติเมื่อแก้ไฟล์ ดีต่อการ deploy ผ่าน WP Pusher
- ไม่มีปลั๊ก SEO ที่ขัดกับ schema ของธีม และ guard เขียนไว้ดี ถ้าจะลง RankMath/Yoast ภายหลังก็ไม่ชนกัน
- page.php / single.php มี breadcrumb ที่รองรับ parent page และหมวดหมู่ ทำให้โครง internal linking ชัด

### 3.3 กฎ internal linking

- โมเดล Hub-and-spoke: ทุกบทความ (spoke) ต้องลิงก์กลับ pillar ของหมวดตัวเองด้วย contextual link อย่างน้อย 1 จุด และ pillar ต้องลิงก์ลงทุก spoke ในหมวด (สร้าง topical cluster ปิดวง). 1 บทความ = 1 primary category เสมอ เพราะ single.php ใช้ category แรกทำ breadcrumb และ related-posts query (category__in กับ cat แรก) ตั้ง primary category ใน WordPress ด้วยปลั๊ก Yoast/Rank Math หรือจัดลำดับ category ให้หมวดหลักมาก่อน
- Contextual link ต้องอยู่ในเนื้อความ (in-content) ไม่ใช่แค่ใน related-posts ที่ธีม generate ให้ และต้องใช้ anchor เป็นคีย์เวิร์ดเชิงความหมาย (descriptive anchor) ห้ามใช้ 'คลิกที่นี่'/'อ่านต่อ' เป็น anchor หลัก เช่นลิงก์ไปหน้า backtest ใช้ anchor 'วิธีอ่านผล backtest' ไม่ใช่ 'ดูที่นี่'
- แต่ละบทความใส่ in-content link 3 ถึง 6 จุด: (1) ขึ้น pillar หมวดตัวเอง, (2) ข้ามหมวด (cross-cluster) 1 ถึง 2 จุดไปหมวดที่ใกล้เคียงตาม funnel เช่น basics→mt5→testing→trust, (3) ลงลึก spoke พี่น้องในหมวดเดียวกัน 1 จุด, (4) ลิงก์ commercial 1 จุดไปหน้า /pricing/ หรือหน้าแรก ตามความเหมาะสมของ intent ห้ามยัด commercial link ในบทความ informational ต้นกรวยจนดูขายของ
- Funnel direction ของ cross-cluster link: ให้ลิงก์ไหลตามเส้น basics (รู้จัก) → mt5/risk (ลงมือ) → testing (ประเมิน) → trust (ตัดสินใจ) → แบรนด์ (หน้าแรก/pricing) บทความปลายกรวย (trust, testing) ลิงก์กลับหน้าแรกและ /pricing/ ได้บ่อยกว่า บทความต้นกรวย (basics) เน้นลิงก์ไป pillar และ subpage ความรู้ ไม่เร่งขาย
- Breadcrumb (มีอยู่แล้วใน single.php: หน้าแรก > หมวด > ชื่อบทความ) ให้คงไว้และเพิ่ม BreadcrumbList JSON-LD ใน single.php เพื่อให้ Google แสดง breadcrumb ใน SERP (ตอนนี้ธีม emit แค่ BlogPosting/Org/WebSite/FAQ ยังไม่มี BreadcrumbList) นี่คือ internal-link signal ที่ Google อ่านได้ ช่วยกระจาย authority ลงหมวดและกลับหน้าแรก
- Related-posts rail ที่ธีม generate อัตโนมัติ (จาก category แรก, สูงสุด 9 โพสต์) ทำงานได้ดีก็ต่อเมื่อแต่ละหมวดมีบทความพอ ช่วงแรกที่บทความน้อย ให้พึ่ง in-content contextual link เป็นหลัก อย่าพึ่ง related-rail อย่างเดียว และจัด primary category ให้ถูกเพื่อให้ rail แนะนำบทความในคลัสเตอร์เดียวกัน
- หน้า pillar และ subpage (/backtest/ /forward-test/ /pricing/ /how-to-install/ /risk-disclosure/) ที่มีอยู่ ควรได้รับ inbound internal link จากบทความ blog ที่เกี่ยวข้องเสมอ (อย่างน้อยหน้า subpage ละ 2 ถึง 3 บทความชี้เข้า) เพื่อกระจาย link equity จาก blog ไปหน้า commercial ที่หน้าแรกชี้อยู่แล้ว
- เพิ่ม section หรือ block 'อ่านบทความที่เกี่ยวข้อง' ในหน้า subpage commercial เช่นใน /backtest/ ให้ลิงก์ไป pillar 'อ่านผล Backtest/Forward Test' และบทความหมวด testing เพื่อให้ link ไหลสองทาง (blog↔commercial) ไม่ใช่ทางเดียว เพิ่มเป็น setting ใน Customizer ตามหลักการ customizer-driven ห้าม hardcode
- ป้องกัน keyword cannibalization: pillar 'ติดตั้ง EA บน MT5' (ทั่วไป) กับหน้า /how-to-install/ (เฉพาะ FENIX) ต้องแยก intent ให้ชัดในหัวข้อและ meta และลิงก์หากันชัดเจน อย่าให้สองหน้าเล็ง query เดียวกัน ทำ keyword map ก่อนเริ่มเขียน (สัปดาห์ตั้งค่า 2026-06-22..28) เพื่อ assign 1 query หลัก = 1 หน้า

- ใช้ Thai slug (สลัก URL เป็นภาษาไทย) สำหรับบทความและ pillar เป็นค่าเริ่มต้น เพราะ WordPress + UTF-8 รองรับ และ Google index/แสดง Thai slug ได้ดี อีกทั้งตรงกับคีย์เวิร์ดที่คนไทยค้น (exact-match ในภาษาเดียวกับ query) เช่น /ea-คืออะไร/ มากกว่าทับศัพท์ /ea-kuu-arai/ ที่ไม่มีใครค้น

- ห้ามใส่ปี/วันที่ลงใน slug ของบทความ evergreen (เช่นอย่าใช้ /ea-คืออะไร-2026/) เพื่อให้ใช้ซ้ำได้โดยไม่ต้อง 301 ทุกปี ใช้วันที่ที่ระบบ WordPress แสดง (get_the_date ใน single.php) บอกความสดแทน และอัปเดต dateModified ผ่านการแก้บทความ
- ตั้ง permalink structure ของ WordPress เป็น /%postname%/ (Post name) ไม่ใช่ค่าเริ่มต้นที่มี ?p= หรือ /%category%/%postname%/ เพราะ single.php breadcrumb แสดงหมวดผ่าน get_category_link อยู่แล้ว ถ้าฝัง category ใน URL จะทำให้ slug ยาวและย้ายหมวดยาก (ต้อง 301) ทำในสัปดาห์ตั้งค่า 2026-06-22..28
- แต่ละ slug กระชับ 3 ถึง 6 คำหลัก ใช้ขีดกลาง (-) คั่นคำ ไม่ใช้ช่องว่างหรือ underscore ไม่ใส่ stop word ฟุ่มเฟือย และต้อง unique ทั้งเว็บเพื่อเลี่ยงชนกับ slug หน้าที่มีอยู่ (backtest, forward-test, pricing, how-to-install, risk-disclosure ห้ามซ้ำ)
- slug ของ category archive ใช้ตามที่กำหนดในหมวด (ea-basics, metatrader5, risk-management, backtest-forward, ea-trust, fenix-updates) เป็นอังกฤษล้วน อ่านง่าย เสถียร และเป็นหน้า archive ที่ได้ inbound link จาก breadcrumb ทุกบทความในหมวด อย่าเปลี่ยน slug หมวดหลังเริ่มใช้ (จะ 301 ยกชุด)
- ถ้าจำเป็นต้องเปลี่ยน slug หลังเผยแพร่ ให้ตั้ง 301 redirect เสมอ (ปลั๊ก Redirection หรือ SEO plugin) ห้ามปล่อย 404 เพราะจะเสีย link equity ที่สะสมจาก internal link และ backlink

### 5.2 KPI

- Brand lock: คำว่า "FENIX PRO EA" อยู่อันดับ 1 และ 10 ผลแรกอย่างน้อย 7 จาก 10 เป็น property ของเราเอง (ภายในสิ้น Phase 2)

- เพื่อนใหม่ LINE OA และจำนวนแชตเปิดใหม่ต่อสัปดาห์ที่ระบุที่มาจากบทความ/โซเชียลได้

- จำนวน backlink/แหล่งอ้างอิงคุณภาพที่ได้ (Myfxbook, YouTube embed, Pantip/Blockdit, เพจ collab) นับเฉพาะที่ relevant สายเทรดไทย

- สัดส่วน engaged sessions และเส้นทาง บทความ -> หน้าแรก -> คลิก LINE (วัดว่าคอนเทนต์ป้อนแบรนด์จริง ไม่ใช่ traffic ลอย)
